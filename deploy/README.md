# Развёртывание

Здесь описано, что делает человек руками. Автоматизации подключения доменов нет и не
планируется: домен — предмет договорённости, а не функция приложения
(`docs/PROCESS.md`, раздел 8).

## Что из чего состоит

| Файл | Что делает |
|---|---|
| `Dockerfile` | три стадии: зависимости → сборка → runtime; наружу отдаёт `.output` Nitro, миграции и их запускалку |
| `compose.yaml` | прод-стек: приложение, Postgres, Redis, nginx, Watchtower |
| `nginx.conf` | TLS, зоны ограничения частоты, анонимизация адресов в логах, CSP |
| `proxy-headers.conf` | заголовки к апстриму, общие для всех location |

Сети две. `internal` помечена `internal: true` — база и Redis не имеют выхода в интернет
и портов на хост. Наружу смотрит только nginx.

## Первое развёртывание

1. **DNS.** `A`-запись домена на адрес хоста. Проверить, что он резолвится, до выпуска
   сертификата — certbot проверяет владение через HTTP.

2. **Файлы на хост.** Достаточно каталога `deploy/` и файла `.env` рядом с ним:

   ```
   POSTGRES_PASSWORD=…            # обязательно, стек без него не поднимется
   PUBLIC_BASE_URL=https://polls.bx-shef.by
   APP_IMAGE=ghcr.io/bx-shef/polls:latest
   LOG_LEVEL=info
   ```

3. **Сертификат.** Сначала поднять nginx на 80 порту, чтобы отработала проверка
   `/.well-known/acme-challenge/`, затем:

   ```bash
   make cert DOMAIN=polls.bx-shef.by EMAIL=…
   ```

   Обновление — задачей cron на хосте: `certbot renew` плюс `nginx -s reload`.

4. **Запуск.**

   ```bash
   make prod-pull
   make prod-up
   make prod-migrate       # схема накатывается одноразовым запуском того же образа
   ```

5. **Проверка.** `curl -s https://polls.bx-shef.by/api/health` должен вернуть
   `"status":"ok"` и `db`/`redis` в состоянии `ok`. `degraded` с `db: down` — миграции
   не накатились или пароль разошёлся с тем, что в `.env`.

## Обновление

Watchtower проверяет реестр раз в пять минут и подменяет только контейнеры с меткой
`com.centurylinklabs.watchtower.enable=true` — то есть само приложение. База, Redis и
nginx не трогаются никогда: подменить базу под нагрузкой из-за нового тега — не та цена,
которую стоит платить за удобство.

Миграции Watchtower не накатывает. Если релиз меняет схему — `make prod-migrate` руками,
до выкатки образа.

## Домен клиента

Второй `server`-блок в `nginx.conf` со своим `server_name` и своим сертификатом, плюс
`portals.public_host` у нужного портала. Ссылки на анкету генерируются от этого поля,
поэтому уже выданные ссылки на старом домене продолжают работать, пока живёт его
сертификат.
