# Опросы клиентов для Битрикс24

Облачное приложение Маркета Битрикс24. Менеджер или робот отправляет клиенту ссылку на опрос,
клиент проходит его на публичной странице без доступа к порталу, результат возвращается в CRM:
запись в таймлайн, элемент смарт-процесса «Опрос», балл в пользовательское поле сущности.

Код приложения — `shef.survey`, публичный домен по умолчанию — `polls.bx-shef.by`.

## В каком порядке читать

1. **`CLAUDE.md`** — правила проекта: как работать с документацией Битрикс24, инварианты с ценой
   нарушения, команды, запреты, процесс pull request. Первое, что читает любой, кто садится
   за код, включая ИИ-ассистента.
2. **`DAY-ONE.md`** — план первых суток чек-листом.
3. **`docs/PROCESS.md`** — архитектура и сквозной путь, раздел «почему сделано именно так».
4. **`docs/PROJECT_MAP.md`** — статус частей и что мешает выпуску.
5. **`docs/BACKLOG.md`** — открытые вопросы и то, что отложено осознанно.

Остальное — по надобности: `docs/market-graphics.md` (задание дизайнеру), `legacy/` (разбор старого
решения заказчика, нужен при написании адаптера миграции), `tools/survey-audit/` (методика аудита
опросного инструмента, переносимый артефакт).

## Разработка

Нужны Node.js 22 и pnpm 10. Postgres и Redis поднимаются в Docker.

```bash
cp .env.example .env      # править не обязательно: значения по умолчанию рабочие
make up                   # postgres + redis в фоне
pnpm install
pnpm db:migrate           # накатить схему
pnpm dev                  # http://localhost:3000
```

Приложение переживает отсутствие Postgres и Redis: страницы отдаются, `/api/health` показывает
`degraded` и называет, что именно недоступно. Это нужно, чтобы каркас можно было запустить
до того, как поднята инфраструктура.

### Команды

```bash
pnpm dev            # разработка
pnpm check          # слои + линт + типы + тесты — единый гейт перед пушем
pnpm test           # только тесты
pnpm build          # сборка
pnpm db:generate    # сгенерировать миграцию по изменению схемы
pnpm db:migrate     # накатить миграции
```

`make help` покажет операционные команды: сборка образа, прод-стек, логи, миграции в контейнере.

## Деплой

Трёхстадийный `deploy/Dockerfile` (зависимости → сборка → runtime), прод-стек — в
`deploy/compose.yaml`: Postgres и Redis без портов на хост во внутренней сети, наружу смотрит
только nginx. Обновление образа — Watchtower по метке. Подробности и порядок первого
развёртывания — в `deploy/README.md`.

## Состояние

Каркас: приложение поднимается локально, в CI и в Docker, `/api/health` отвечает. Логики опросов
пока нет — см. `DAY-ONE.md` и `docs/PROJECT_MAP.md`.
