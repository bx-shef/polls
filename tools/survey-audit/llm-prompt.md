# Обвязка для LLM: из метрик — в отчёт для человека

Схема: **коллектор → `survey-audit.mjs` → JSON метрик → LLM → отчёт**.

Принцип, от которого не отступать: **модель не считает и не ходит в базу.** Все числа посчитаны
детерминированно и воспроизводимо; LLM отвечает за формулировки, приоритеты и рекомендации. Иначе
одни и те же данные будут давать разные цифры от запуска к запуску, и доверия к отчёту не будет.

Транспорт — любой OpenAI-совместимый клиент (BitrixGPT, DeepSeek) через пакет `openai` с подменой
`baseURL`. Вызов tool-less: на вход текст, на выходе JSON с валидацией на нашей стороне.

---

## Системный промпт

```
Ты консультант по системам клиентских опросов. Тебе дают JSON с посчитанными метриками
аудита. Твоя работа — объяснить, что эти цифры значат, и предложить, что чинить.

Жёсткие правила:
1. Не выдумывай и не пересчитывай числа. Используй только те, что есть во входном JSON.
   Если для вывода не хватает данных — так и скажи, не достраивай.
2. Не интерпретируй вопросы с вердиктом insufficient-data. Их можно упомянуть одной
   строкой как «данных мало», но выводов по ним не делай.
3. Средний балл не является главной метрикой, если distribution.averageIsMeaningful = false.
   В этом случае говори о долях по корзинам и об индексе, а среднее упоминай только как
   иллюстрацию того, что оно неинформативно.
4. Индекс называй NPS-подобным, а не NPS. Канонический NPS считается по одному вопросу
   «порекомендуете ли вы нас», здесь это заимствование формы.
5. Дефекты целостности (ORPHANED_RESPONSES) ставь выше любых выводов о конверсии:
   при потерянных данных конверсия занижена, и об этом надо предупредить явно.
6. Пиши по-русски, простыми словами, без маркетингового тона. Владелец портала —
   не аналитик; ему нужно понять, что не так и что с этим делать.
7. Каждая рекомендация должна быть проверяемой: что именно поменять и какой метрике
   это должно помочь.

Ответ — строго JSON по схеме, без пояснений вокруг.
```

## Пользовательское сообщение

```
Данные аудита за период <период>, портал <название>.

<сюда JSON целиком>

Сделай отчёт по схеме.
```

## Схема ответа

```json
{
  "summary": "2–4 предложения: что происходит с опросами в целом",
  "health": "good | warning | critical",
  "findings": [
    {
      "title": "Короткий заголовок",
      "severity": "high | medium | low",
      "what": "Что показывают данные — с конкретными числами из входного JSON",
      "why": "Почему так получилось",
      "action": "Что сделать",
      "metric": "Какая метрика должна измениться, если сделать"
    }
  ],
  "questionsToDrop": ["survey/question", "..."],
  "questionsToKeep": ["survey/question", "..."],
  "notEnoughData": ["survey/question", "..."]
}
```

## Валидация на нашей стороне

Модель может ошибиться, поэтому после ответа проверяем механически:

- каждое число, встреченное в `what`, есть во входном JSON (сверка по строковому вхождению);
- в `questionsToDrop` попали только вопросы с вердиктом `ritual`;
- в `questionsToKeep` — только `working`;
- ни один вопрос с `insufficient-data` не попал ни в drop, ни в keep;
- `health` согласован с дефектами: есть `high` — не может быть `good`.

Не прошло — повторяем запрос с добавленным замечанием. Повторов не больше двух, дальше отдаём
отчёт без интерпретации, на голых метриках: он менее приятный, но верный.

## Что стоит держать в контексте модели

Кроме JSON метрик, полезно передавать формулировки вопросов — с кодами вроде `UF_HQ_PACKAGE_4`
модель ничего осмысленного не скажет, а с текстом «техническая вёрстка и подготовка в печать»
сможет объяснить, почему на этом вопросе копятся пропуски. Формулировки берутся из конфигурации
опроса, а не из данных.

## Границы применимости

Отчёт отвечает на вопросы «работает ли инструмент» и «какие вопросы лишние». Он **не** отвечает на
вопрос «довольны ли клиенты» — для этого нужны сами ответы, а не их статистика. И он ничего не знает
о причинах: падение конверсии видно, а вот сменился ли менеджер, поменялся ли шаблон письма или
клиенты просто устали — из этих данных не следует. Это тема для разговора с заказчиком, и хороший
отчёт заканчивается такими вопросами, а не притворяется, что ответил на них.
