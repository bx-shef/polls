# Развёртывание

Приложение встаёт на **общий хост**, устроенный так же, как у `client-bank-alfa-by`.
Это определяет почти всё, что здесь написано.

## Что уже есть на хосте, а чего нет у нас

Один раз и на все проекты на хосте подняты:

- **`nginx-proxy` + `acme-companion`** на внешней сети `proxy-net`. Маршрутизирует по
  `VIRTUAL_HOST` и сам выпускает сертификат по `LETSENCRYPT_HOST`.
- **Один Watchtower** с `--label-enable`. Подхватывает контейнеры по метке
  `com.centurylinklabs.watchtower.enable=true`.

Поэтому у нас **нет** своего nginx, своего Watchtower и certbot. Это не упущение:
второй Watchtower конфликтует по `container_name` и плодит двойные перезапуски,
а второй nginx просто не займёт уже занятые 80 и 443.

| Файл | Что делает |
|---|---|
| `Dockerfile` | три стадии: зависимости → сборка → runtime; отдаёт `.output` Nitro, миграции и их запускалку |
| `compose.yaml` | приложение, Postgres, Redis; наружу — только через `proxy-net` |

Сети две. `proxy-net` внешняя — через неё нас видит прокси и через неё же приложение
ходит в REST портала. `dbnet` помечена `internal: true` — у базы и Redis нет ни портов
на хост, ни выхода в интернет.

## Что переехало в приложение

Свой nginx нёс не только TLS. Общий прокси про Битрикс24 ничего не знает, поэтому
в приложение переехали:

- **CSP** — `server/utils/security-headers.ts`, проставляется через `routeRules`.
  У приложения в iframe портала `frame-ancestors` перечисляет региональные домены
  Битрикс24; у публичной страницы — `'none'`.
- **`X-Robots-Tag`** для `/s/**`.

Не переехало и пока отсутствует:

- **Ограничение частоты.** Было зонами nginx, теперь его нет вовсе. Появится вместе
  с публичной страницей — по замыслу оно всё равно должно считать и по токену, а не
  только по адресу (`docs/PROCESS.md`, раздел 6).
- **Анонимизация адресов в логах.** Access-лог теперь пишет общий `nginx-proxy`, и его
  формат — не наша зона ответственности. Наши собственные логи адресов не пишут.

## Откуда берётся образ

CI публикует `ghcr.io/bx-shef/polls` только с `main`. С ветки образ собирается ради
проверки, что `Dockerfile` жив, но в реестр не уезжает.

Пакеты GHCR приватны по умолчанию, поэтому хосту нужен `docker login ghcr.io` токеном
с правом `read:packages`.

## Первое развёртывание

1. **DNS.** `A`-запись домена на адрес хоста. Убедиться, что резолвится, **до** первого
   подъёма: `acme-companion` выпустит сертификат сразу, и на неготовом DNS попытка
   сгорит вместе с лимитом.

2. **Файлы на хост.** Каталог `deploy/`, `Makefile` и `deploy/.env`:

   ```
   DOMAIN=polls.bx-shef.by            # обязательно
   LETSENCRYPT_EMAIL=…                # можно пустым
   POSTGRES_PASSWORD=…                # обязательно
   APP_IMAGE=ghcr.io/bx-shef/polls:latest
   LOG_LEVEL=info
   ```

   Проверить, что compose видит переменные: `docker compose -f deploy/compose.yaml config`.

3. **Убедиться, что сеть на месте.** `docker network ls | grep proxy-net` — она создаётся
   вместе с `nginx-proxy`, не нами. Если её нет, значит общая инфраструктура на этом хосте
   ещё не поднята, и начинать надо с неё.

4. **Запуск.**

   ```bash
   make prod-pull
   make prod-up
   make prod-migrate       # схема накатывается одноразовым запуском того же образа
   ```

   Сертификат выпустится сам; первый раз это занимает до минуты.

5. **Проверка.**

   ```bash
   curl -s https://polls.bx-shef.by/api/health
   ```

   Ожидается `"status":"ok"` и `db`/`redis` в состоянии `ok`.

   | Что видно | Что это значит |
   |---|---|
   | `db: down` | база не отвечает: не поднялся контейнер или пароль разошёлся с `deploy/.env` |
   | `redis: down` | контейнер Redis не поднялся, смотреть `$(PROD) logs redis` |
   | `db: off` / `redis: off` | переменная окружения не доехала до контейнера приложения |
   | 502 от прокси | приложение ещё поднимается либо упало, смотреть `make prod-logs` |
   | сертификат не выпустился | смотреть логи `acme-companion` на хосте; чаще всего DNS ещё не разошёлся |

   **`status: ok` не означает, что миграции накачены.** Проверка выполняет `select 1`,
   а он проходит и на пустой базе. Сверяйтесь по списку таблиц:

   ```bash
   docker compose -f deploy/compose.yaml exec db psql -U survey -d survey -c '\dt'
   ```

   Причину состояния `down` наружу не отдаём намеренно: текст ошибки драйвера несёт
   имена хостов, порты и причины отказа аутентификации, а эндпоинт открыт анонимно.
   Подробности — в `make prod-logs`.

## Обновление

Общий Watchtower проверяет реестр и подменяет контейнеры с меткой — у нас это только
приложение. База и Redis не трогаются никогда.

Миграции Watchtower не накатывает. Если релиз меняет схему — `make prod-migrate` руками,
**до** того, как новый образ уедет в реестр. Это единственное место, где автообновление
опасно: оно подменит контейнер по расписанию, не спросив, готова ли под него база.

## Домен клиента

`nginx-proxy` маршрутизирует по `VIRTUAL_HOST`, поэтому второй домен — это второй
`VIRTUAL_HOST` (через запятую) плюс `LETSENCRYPT_HOST`, и `portals.public_host`
у нужного портала. Ссылки на анкету генерируются от этого поля, поэтому уже выданные
ссылки на старом домене продолжают работать.
